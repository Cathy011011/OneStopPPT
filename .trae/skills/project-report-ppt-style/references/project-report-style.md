# 项目报告 PPT 风格手册

来源基线：`f:\Codex\PPT自动化\访谈\项目报告.pptx`

## 1. 客观基线

这套参考稿不是“纯视觉展示型 PPT”，而是典型的研究报告型、结论驱动型商业汇报。

| 项目 | 结果 | 含义 |
| --- | ---: | --- |
| 幻灯片总数 | 60 | 允许长篇结构化叙事，不追求极少页数 |
| 页面比例 | 16:9 | 全部新页都应保持宽屏 |
| 母版数量 | 11 | 已形成多种稳定页面角色 |
| 原生形状/文本对象 | 752 | 页面以原生可编辑对象为主 |
| 图表 | 71 | 数据分析是核心叙事方式 |
| 表格 | 60 | 对比、弱项梳理、结构化说明大量依赖表格 |
| 图片媒体 | 49 | 图片只占辅助角色 |
| 连接线 | 59 | 用于流程、关系、指向，不泛滥装饰 |

## 2. 整体风格判断

### 2.1 风格关键词

- 理性
- 克制
- 调研报告感
- 黑白灰主导
- 数据先行
- 结论明确
- 强结构，不炫技

### 2.2 页面气质

- 很少使用高饱和多彩装饰。
- 标题通常直接承担结论或章节功能。
- 大多数页面都有明显的“主图/主表 + 一段解释”的结构。
- 与其说在“做设计”，不如说在“做有秩序的数据表达”。

## 3. 色彩系统

主题是深浅双底切换，但整体以灰阶为主，强调色很克制。

| 角色 | 色值 | 用法 |
| --- | --- | --- |
| 深色基底 | `#181818` | 封面、章节页、深色内容页 |
| 浅色基底 | `#FBFBFB` | 常规正文页背景 |
| 中性深灰 | `#3E3E38` | 次级深色块、边框或重点分区 |
| 中性灰 1 | `#595757` | 次级标题、弱化信息 |
| 中性灰 2 | `#717171` | 说明文字、辅助标签 |
| 中性灰 3 | `#898989` | 非焦点线条、参考线 |
| 中性灰 4 | `#9FA0A0` | 网格线、退后信息 |
| 中性灰 5 | `#B5B5B6` | 辅助边界、最弱层文字 |
| 焦点橙 | `#F06124` | 唯一重点、核心提示 |
| 风险红 | `#C00000` / `#FF0000` | 风险、下降、负向差异 |
| 正向绿 | `#4B8D56` / `#006100` | 增长、优秀、达标 |
| 对照蓝 | `#4654FF` / `#2274AC` / `#0070C0` | 对照组、辅助系列 |

### 色彩使用规则

- 默认是灰阶主体加 1 个焦点色。
- 红绿蓝只在有明确语义时使用，不做装饰。
- 一张图表里尽量控制在 1 个焦点色 + 灰阶，特殊情况再加正负色。
- 若全页已经是深底，彩色只保留给重点对象或重点数据。

## 4. 字体系统

| 类别 | 字体 |
| --- | --- |
| 中文 | `Alibaba PuHuiTi 2.0 55 Regular` |
| 英文/数字 | `DIN Pro` |

### 常用字号层级

| 层级 | 范围 | 用法 |
| --- | --- | --- |
| 超大标题 | 40-54 pt | 封面、章节主张 |
| 页面标题 | 32-44 pt | 章节页或关键内容页标题 |
| 关键指标/结论标签 | 20-32 pt | 排名、分数、核心提示 |
| 正文/表头 | 14-18 pt | 常规说明、表格标题 |
| 图表标签/脚注 | 8-12 pt | 坐标轴、图例、样本说明 |

### 对齐习惯

统计上，居中出现最多，但这是因为章节编号、标签、图中卡片很多；真实写正文时仍以左对齐为主。

- 大标题可居中。
- 正文段落、洞察说明、表格文字优先左对齐。
- 数值、页码、尾注可右对齐。
- 不把长段正文做成居中诗歌排版。

## 5. 文字编排方法

### 5.1 标题风格

这份 PPT 的标题通常有三类：

1. **章节型**  
   例如“项目目的与解决方案设计”“销售服务的满意度评价及优先调整方向”
2. **结论型**  
   例如“某品牌总体SSI服务满意度排名第四，位于行业中等”
3. **说明型**  
   例如“某品牌2023年H1和H2 SSI得分及排名情况”

### 5.2 页面内部文案顺序

常见顺序是：

`标题 -> 图表/表格主体 -> 一段总结说明 -> 页码/样本/口径`

换句话说，说明文字不是主角，主角是结构化证据。

### 5.3 文案密度控制

- 同类弱项汇总页可以文字多，但仍以表格容器承载。
- 图表页的正文说明一般只有 1 段，不会放 3 到 4 段大块文字。
- 当证据很多时，宁可拆页，也不把字号压得过小。

## 6. 版式逻辑

### 6.1 典型页面骨架

1. 顶部标题区
2. 中部主图或主表区
3. 旁侧或底部解释区
4. 页码和辅助信息区

### 6.2 留白策略

- 主图占比通常很大，页面不会被碎卡片切得太散。
- 辅助信息通过灰色、细线、较小字号退后。
- 标题与主体之间距离稳定，页面边界意识很强。

### 6.3 母版节奏

11 个母版说明它不是单一模板硬套，而是有章节页、目录页、摘要页、数据页、建议页、洞察页等多种稳定骨架。

## 7. 数据分析表达风格

这是这份参考稿最重要的部分。

### 7.1 常见分析动作

- H1 vs H2 对比
- 本品 vs 竞品对比
- 总体 vs 分战区对比
- 因子 vs 要素拆解
- 强项 vs 弱项归纳
- 自评 vs 战胜战败 vs 犹豫用户三类视角对照

### 7.2 图表选型规则

| 场景 | 首选表达 |
| --- | --- |
| 排名 | 横向条形图 |
| 时间/阶段对比 | 折线图或分组柱形图 |
| 因子多维对比 | 条形图、小倍数图、矩阵式并列图 |
| 弱项清单 | 表格、评分矩阵、汇总面板 |
| 战区/区域分析 | 排名图 + 分区域小图 |
| 流程/关系 | 箭头流程图 |
| 定性洞察 | 标签化引语或简短结论卡 |

### 7.3 数据页写法

- 标题直接告诉读者该看见什么。
- 图上尽量直接标数，减少来回对坐标轴。
- 置信度、样本量、是否显著等方法说明，通常以小字写在图旁或图下。
- 对比时，焦点对象必须稳定高亮。

### 7.4 弱项与建议页写法

- 先总结弱项数量和归类方式。
- 再落到服务环节或执行动作。
- 建议页通常有“问题 -> 对应策略”的强映射，不空谈。

## 8. 表格风格

- 这份参考稿大量使用原生表格。
- 表格承担的不只是罗列，还承担分类、对比、判断和建议承接。
- 表头清晰、列宽稳定、数字与文字排法一致。
- 同一维度的对比项顺序尽量固定。

## 9. 图片与图形使用原则

- 图片是证据补充，不是主视觉中心。
- 若图片出现，通常用于说明场景、案例、界面或流程触点。
- 连接线和箭头只在确实需要解释路径与关系时出现。
- 不引入无意义插画、抽象背景图、渐变装饰块。

## 10. 章节结构偏好

从标题和页序可以看出，这份参考稿的结构是：

1. 封面
2. 摘要
3. 项目设计与研究方法
4. 主要发现和优先改进项
5. 分主题深挖分析
6. 行业洞察与策略借鉴

也就是说，它喜欢先给“总览与方法”，再给“分模块证据”，最后补“外部洞察和启发”。

## 11. 写新 PPT 时的复写规则

### 必须保留

- 16:9 宽屏
- 深浅底切换
- 黑白灰主色
- 中文普惠体、数字 DIN Pro
- 结论驱动标题
- 图表/表格优先的证据表达
- 清晰页型和章节节奏

### 可以按内容适度变动

- 焦点色的出现频率
- 某些页是以表格还是条形图呈现
- 章节命名方式
- 是否需要“行业洞察”尾章

### 不建议偏离

- 不要突然做成彩色互联网营销风。
- 不要改成大面积插画封面。
- 不要一页堆满多张小图和多个卡片。
- 不要弱化数据口径说明。

## 12. 交付前检查

1. 标题是否直接表达当前页目的或结论。
2. 是否一页只有一个主焦点。
3. 图表颜色是否有语义，而不是随便配色。
4. 表格是否可读，列宽和对齐是否稳定。
5. 正文是否过密，是否需要拆页。
6. 样本量、单位、时间范围、统计说明是否交代清楚。
7. 文本、线条、表格、图表是否尽量保持原生可编辑。
