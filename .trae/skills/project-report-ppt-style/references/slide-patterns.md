# 页面结构与页型模板

本文件把 `项目报告.pptx` 的 60 页内容拆成“章节结构 + 可复用页型”。

## 1. 章节地图

| 页码 | 角色 | 内容特征 |
| --- | --- | --- |
| 1 | 封面 | 深底、大标题、单一主题句 |
| 2 | 目录 | 章节编号列表，建立阅读地图 |
| 3-5 | 项目摘要 | 先讲总体发现，偏表格汇总 |
| 6 | 第一章章节页 | 进入项目目的与设计说明 |
| 7-12 | 方法与分析逻辑 | 项目目的、样本设计、分析口径、弱项分类 |
| 13-20 | 主要发现与建议 | SSI/CSI 弱项汇总，分销售/交付/售后建议 |
| 21 | 全报告框架页 | 后续三大版块总览 |
| 22 | 第二章章节页 | 进入销售服务满意度分析 |
| 23-47 | 数据深挖主体 | 排名、分区、因子、要素、战胜战败、犹豫用户、战区分析 |
| 48 | 第五章章节页 | 进入线上平台满意度 |
| 49-53 | 线上平台分析 | 分渠道、分品牌、最认可/最不认可项 |
| 54 | 第六章章节页 | 行业洞见 |
| 55-60 | 行业洞察与策略案例 | CRM、用户旅程、共创机制、生命周期运营 |

## 2. 这份参考稿最常见的页型

### 页型 A：封面页

**用途**：整份报告开场。  
**骨架**：

- 深色背景
- 1 行主标题
- 少量辅助说明
- 几乎没有额外装饰

**复写规则**：

- 标题要完整明确，不写过于抽象的文学句。
- 封面不要塞副标题墙。

### 页型 B：目录页

**用途**：建立章节框架。  
**骨架**：

- 多个章节编号
- 章节名列表
- 排列规整、信息密度中等

**复写规则**：

- 目录页是导航，不承载结论。
- 编号与标题层级要清楚分开。

### 页型 C：摘要汇总页

**用途**：快速给出研究结果总览。  
**骨架**：

- 标题说明“项目摘要 x/x”
- 主体常为表格
- 左右或上下分区展示不同主题

**复写规则**：

- 先放结论性摘要，再放说明。
- 表格要用来组织事实，不要塞成长段原文。

### 页型 D：章节过渡页

**用途**：进入新的大模块。  
**骨架**：

- 大编号
- 大章节标题
- 辅助说明一句

**复写规则**：

- 保持节奏感，信息不要过满。
- 章节过渡页不是内容页，不提前剧透太多细节。

### 页型 E：方法设计页

**用途**：说明项目目的、样本、分析口径、定义方法。  
**骨架**：

- 上方标题
- 中间流程图、分类图、结构图或说明表格
- 底部或侧边补充解释

**复写规则**：

- 把方法讲清楚，但版面依旧要有层级。
- 复杂说明优先结构图，不优先大段文字。

### 页型 F：排名对比页

**用途**：展示品牌/区域/阶段之间的排名关系。  
**骨架**：

- 标题直接说明比较对象
- 主图为条形图或柱形图
- 图旁有一段结论说明

**复写规则**：

- 必须高亮本品或焦点对象。
- 图下注明样本量、显著性、是否纳入平均值等口径。

### 页型 G：因子分析页

**用途**：把总分拆成多个服务因子。  
**骨架**：

- 同一页并列多个因子图
- 重点因子高亮
- 一段文字总结强弱势

**复写规则**：

- 因子顺序要稳定。
- 同类图之间坐标或尺度尽量一致，便于横向比。

### 页型 H：要素展开页

**用途**：从因子再拆到更细项的服务要素。  
**骨架**：

- 页面标题说明场景
- 中部主图或评分矩阵
- 底部文字说明“哪些项领先/落后”

**复写规则**：

- 适合承接“原因解释”，不要只给分数不给判断。
- 项目多时可拆两页，避免字号过小。

### 页型 I：弱项汇总页

**用途**：识别优先改进问题。  
**骨架**：

- 标题说明“弱项汇总”
- 表格或矩阵承载问题列表
- 上方一句话先说明共有多少项、如何筛出

**复写规则**：

- 一定要交代筛选逻辑，如“按重视度加权”“按本品与竞品差值筛出”。
- 弱项名称要短，便于后续建议页承接。

### 页型 J：建议页

**用途**：把问题转成总部/区域/终端动作。  
**骨架**：

- 标题通常带“建议”
- 左侧问题分类，右侧动作建议，或用表格一一对应
- 说明语气具体、执行导向

**复写规则**：

- 建议要和前文弱项一一对应。
- 避免空泛词，如“持续优化”“加强提升”而没有动作对象。

### 页型 K：战胜战败/犹豫用户分析页

**用途**：从不同人群视角看同一服务问题。  
**骨架**：

- 同一页双栏或多栏对照
- 图表加一段解释
- 标题明确样本人群

**复写规则**：

- 双栏对照时，颜色与标签必须绝对统一。
- 每页只讲一个核心差异，不要混杂多个样本人群结论。

### 页型 L：分战区/分渠道拆解页

**用途**：展示区域或渠道差异。  
**骨架**：

- 主排名图
- 多个小图或分区标签
- 一段指出优先改进区域/渠道

**复写规则**：

- 地域/渠道顺序固定。
- 若页面过密，优先拆页，不牺牲可读性。

### 页型 M：行业洞察页

**用途**：跳出本项目，给行业案例与启发。  
**骨架**：

- 标题偏策略和方法
- 图示、模型、流程、生命周期框架较多
- 文字说明比数据页稍多

**复写规则**：

- 行业洞察页仍需结构化，不做大段论文式文字。
- 更适合用模型图、阶段图、关系图，而不是普通条形图。

## 3. 后续写新 PPT 时的选页方法

拿到素材后，先判断它属于哪类信息：

| 素材类型 | 优先页型 |
| --- | --- |
| 项目背景/目标 | D、E |
| 样本设计/研究方法 | E |
| 总体结论汇总 | C、I |
| 品牌/区域/阶段排名 | F、L |
| 因子或要素拆解 | G、H |
| 问题归因与优先改进 | I、J |
| 不同人群对照 | K |
| 行业启发/案例借鉴 | M |

## 4. 一份新报告的推荐组装顺序

如果用户后面要你“按这个风格写一份新 PPT”，默认优先采用以下顺序：

1. 封面
2. 目录
3. 项目摘要
4. 研究设计/方法
5. 总体核心发现
6. 分模块深挖
7. 优先改进项
8. 具体建议
9. 行业洞察或案例借鉴
10. 收尾页

## 5. 页面生成时的快速判断

- 这一页有没有唯一主结论？
- 这页最适合图表、表格、流程图，还是摘要表？
- 这页是在“讲发现”，还是在“讲方法”，还是在“给建议”？
- 这一页与前后一页是不是同一个层级？
- 这一页是该拆开，还是已经足够简洁？
