# 项目报告 PPT 风格复写技能

当用户要基于本地私有参考 PPT 的风格继续写新 PPT、改已有 PPT、或先做风格学习再出页时，使用这个 skill。

## 先读这些文件

1. `references/project-report-style.md`
2. `references/slide-patterns.md`
3. `references/project-report-analysis.json`
4. 如果本地参考 PPT 更新了，先运行 `scripts/analyze_ppt_style.ps1`

## 这个 skill 要解决什么

- 把参考 PPT 的字体、层级、版式、颜色、图表与表格习惯，整理成可执行规则。
- 把“调研报告型 PPT”拆成固定页型，减少后续每页从零设计。
- 在写新内容时，保持原参考的证据链结构：`事实/数据 -> 证据呈现 -> 洞察 -> 建议/动作`。
- 让后续交付尽量保持 PowerPoint 原生可编辑，而不是把大段信息做成图片。

## 标准工作流

1. **分析输入**  
   识别用户提供的是访谈纪要、问卷数据、研究结论、竞品对比、还是半成品 PPT。
2. **匹配页型**  
   先从 `references/slide-patterns.md` 中选页面角色，再决定是否要封面、目录、章节页、总结页、因子分析页、弱项汇总页、建议页、行业洞察页。
3. **组织文案**  
   优先保留原始结论和原始口径；标题尽量直接写结论，正文只保留支撑结论所需信息。
4. **选择图表/表格**  
   排名看条形图，趋势看折线图，对比看表格或评分矩阵，流程看箭头流程图，定性证据看引语加主题标签。
5. **套用视觉系统**  
   严格按参考的深底/浅底切换、灰阶主色、少量语义强调色、中文/数字字体分工、字号层级来排版。
6. **质量复核**  
   检查对齐、留白、图例、单位、可编辑性、证据来源、颜色语义是否一致。

## 执行规则

### 1. 文案与叙事

- 不臆造结论、不补造数字、不改写用户未批准的事实。
- 一页只服务一个主结论，避免一页多个竞争焦点。
- 页面正文要短，尽量让图表/表格承担信息主体。
- 当用户给的是原始访谈或研究材料时，先抽取“问题、发现、证据、建议”四层，再写页。

### 2. 版式与视觉

- 统一使用 16:9 宽屏比例。
- 默认优先横向展开，不做手机海报式竖向堆叠。
- 标题、主图、侧注、页码、来源区保持稳定边界。
- 避免把页面做成过度装饰的卡片墙。

### 3. 数据页

- 优先展示相对差异和结论，不让用户自己从一堆数字里找重点。
- 焦点对象可以上强调色，其余对象退到灰阶。
- 图表必须写清单位、样本量、统计口径、时间范围或显著性说明。
- 比较页保持同一排序逻辑，不能这一页按高低排，下一页按品牌顺序排。

### 4. 原生对象要求

- 文本框、表格、图表、线条、箭头、图例、数据卡，优先保持为 PowerPoint 原生对象。
- 只有不可拆解的照片、截图、原始视觉证据才允许作为图片使用。
- 如果图片里包含可重建文字或图表，默认应拆开重做。

## 交付物要求

- 输出新的 PPT 大纲、逐页文案、页面类型建议，或直接生成完整 PPT 时，都必须遵守上述规则。
- 若当前任务只要求“先学习风格”，则先输出结构化风格总结与页面映射，不急着生成新 PPT。
- 若用户继续要求“按这个 skill 写 PPT”，直接沿用本 skill，不重新发明风格规则。

## 资源说明

- `references/project-report-style.md`：风格系统、字体、颜色、图表、文字编排、QA 规则。
- `references/slide-patterns.md`：从 60 页参考稿提炼出的章节结构和页型模板。
