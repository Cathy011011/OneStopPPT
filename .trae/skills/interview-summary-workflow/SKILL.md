# 访谈归纳工作流

当用户给出原始访谈纪要、座谈会笔录、共创会记录或会议逐字稿，希望先整理出结构化总结，再进入 PPT 生成时，使用这个 skill。

## 核心输入

优先使用本地私有材料，推荐放在：

- `f:\Codex\PPT自动化\访谈\02_访谈资料\`

当前项目中的标准输入示例：

1. `归纳总结的提示词(1).docx`
2. `归纳总结的提示词(1).extracted.txt`
3. `座谈会笔录2-7月13日.docx`
4. `座谈会笔录2-7月13日.extracted.txt`

如果 `docx` 仍是二进制不可直读，先在本地提取正文，再继续归纳。

## 这个 skill 要解决什么

- 把长笔录从发言流水账，重组为研究可用的结构化总结
- 保留用户真实观点，同时区分主持人 / 品牌方 / 用户反馈
- 从口语内容里提炼产品、设计、配置、服务、传播可直接使用的结论
- 为后续 `avatr-report-ppt` 生成可编辑 PPT 提供稳定底稿

## 唯一权威方法来源

把下面这份提示词文档视为本项目的标准方法，不再随意改写步骤名：

- `f:\Codex\PPT自动化\访谈\02_访谈资料\归纳总结的提示词(1).docx`
- `f:\Codex\PPT自动化\访谈\02_访谈资料\归纳总结的提示词(1).extracted.txt`

## 标准输出结构

最终归纳稿必须按下面 5 个一级部分输出：

1. 会议概况
2. 核心发现与用户洞察
3. 核心议题研讨结论
4. 会后深访核心洞察
5. 相关建议

如果要给 PPT 使用，建议追加：

6. 可直接转为 PPT 页标题的结论句

## 标准工作流

### 1. 材料拆段

先按会议流程拆分模块，而不是一上来就写总结。每个模块至少给出：

- 模块名称
- 起止内容概括
- 主要发言者
- 该模块产生的有效信息类型
- 是否需要进入最终会议总结

建议优先识别这些模块：

- 会议开场与参会介绍
- 用户自我介绍
- 产品介绍
- 人群画像讨论
- 竞品认知与痛点讨论
- 产品设计共创
- 产品配置共创
- 营销共创
- 价格测试

### 2. 证据抽取

再从笔录里提取能进入汇报的证据，不要直接跳到结论。证据表字段固定为：

- 议题
- 发言者 / 身份
- 原话或接近原话
- 观点归纳
- 情绪倾向：正向 / 负向 / 中性 / 争议
- 可转化的产品含义
- 可归入的总结章节

### 3. 观点归纳

把零散观点合并成研究口径，至少区分：

- 高频共识
- 典型分歧
- 少数但重要观点
- 竞品机会点
- 需进一步验证的问题

归纳时明确区分：

- 事实描述
- 用户感受
- 产品问题
- 商业机会
- 传播表达

### 4. 专项洞察

根据笔录内容，补出这些专题：

- 用户洞察
- 竞品痛点
- 品牌与定位
- 产品设计反馈
- 配置需求
- 行动建议

如果原始材料没有足够依据支撑细项结论，要明确写：

- `现场信息不足，需问卷进一步验证`

### 5. 一键成稿

最后再把前面的证据和专题结论汇总成正式总结稿，不得跳过前面的拆段和证据抽取。

## 写作规则

- 不做流水账总结，按洞察维度重组信息
- 不补造笔录中不存在的数据、用户原话、竞品判断
- 保留高频原话关键词，但不要堆满整页原话
- 对争议点明确写出分歧，不要强行统一成一个结论
- 设计、配置、生态、价格策略等只在有足够证据时下结论
- 对证据不足的细项统一标注：`需问卷进一步验证`

## 与 PPT 流程的衔接

当用户下一步要做 PPT 时，按下面顺序衔接：

1. 用本 skill 先输出 `*_按提示词归纳总结.md`
2. 再把该归纳稿交给 `avatr-report-ppt`
3. 若用户提供了本地参考模板 PPT，再由 `avatr-report-ppt` 按参考模板页型和配色框架生成可编辑 PPT

## 当前项目推荐输出文件

建议把归纳结果存放到：

- `f:\Codex\PPT自动化\访谈\02_访谈资料\座谈会笔录2-7月13日_按提示词归纳总结.md`

## 何时不要直接用这个 skill

- 用户已经给了成熟 PPT，只想微调版面：优先用 `avatr-report-ppt`
- 用户只想学习参考报告风格，不整理访谈内容：优先用 `project-report-ppt-style`
- 用户要直接编辑当前打开的 PowerPoint：优先用 `powerpoint-automation`
